# Phase 14: own-observation print draft

Approved scope: select exactly 24 distinct saved real observation cards, reorder deterministically, preview using the existing collectible/PNG renderer, obtain a server-owned ¥59.9 quote and immutable order-item draft snapshot. Gifted copies remain visible but disabled with “素材未授权”; no other person's original is read. Legacy local-only/example/unsaved/deleted cards are not printable in this flow.

The final 63×88 mm trim plus 3 mm bleed at 300 DPI rounds to 815×1110 px, trim 744×1039 px. The existing renderer remains the only renderer; its logical drawing is mapped onto this output, with crop marks computed from physical dimensions and safety inset at least 6 mm from the output edge. Sharing export is unchanged. Device PNG decode/quality failures remain explicit, never blank successes.

Extend createArtCard with print_quote and print_draft only. Server derives OPENID, reads saved Card/Observation, recognition source, artwork authorization and deletion fences in a doc-only transaction, touching account/observation/artwork generations. Client sends only ordered server card IDs, then quote hash and idempotency key. No client amount, assets, address, owner or payment state is accepted. Quote digest binds ordered immutable snapshots and server SKU; creating a changed selection/source returns quote_changed. Draft replay returns the same draft only while sources remain authorized. No payment/fulfillment transition is exposed; terminal paid/refunded/cancelled rows cannot be recreated through the draft API.

Draft snapshot contains server asset references but no temporary URLs, notes or location. Local storage keeps ordered IDs and safe draft receipt, not addresses. Server drafts are non-financial personal records and join account erasure. Source deletion invalidates later access/replay; snapshot itself is immutable and never becomes a fulfillment request. A future paid snapshot needs separate retention/authorization policy.

External gates: provision printOrderDrafts as server-only, deploy function changes, verify CloudBase concurrent deletion/erasure, device PNG quality, production font/layout and manufacturer specification. Merchant, address collection, PDF/package generation, payment, refunds and fulfillment are deliberately not connected in this slice; gift printing awaits separate explicit authorization.
