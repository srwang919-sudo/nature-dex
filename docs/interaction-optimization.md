## 二、本轮实施：图鉴搜索

**问题**：`library` 页只有全量列表与卡架两种呈现，收藏一多就只能翻页找，是最高频的摩擦点。

**方案**：
- 顶部常驻搜索框（仅在有收藏时出现，空收藏不占位）
- 匹配维度：中文名、学名、科属、地点标签、日期——覆盖用户能想起的任一线索
- 输入即时过滤，不清空原数据（`all` 全量 + `cards` 视图分离）
- 卡架模式下搜索自动回到第 1 张，避免索引越界
- 空结果单独成态："没有匹配的收藏" + 清除按钮，而不是误显示"去拍一张"

**代码**：`native/pages/library/index.js`（`filterCards` / `searchInput` / `clearSearch`）、`index.wxml`、`index.wxss`。

## 三、为什么拍照与保存没在这轮一起改

这两处的冗余步骤来自**识别结果强制需要确认**（`mergeCandidateRoutes` 当前恒定 `needs_confirmation`，`recognized` 状态不可达）。
要真正省掉"确认物种"这一步，必须先做识别链路的路由决策与阈值校准——属于识别准确率专项，且阈值需要用真实识别数据校准，不适合在没数据时拍脑袋改。强行先改 UI 会出现"跳过确认但识别其实不准"的体验倒退。
