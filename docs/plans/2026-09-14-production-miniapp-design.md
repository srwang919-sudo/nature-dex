# 去大自然里生产版体验设计

日期：2026-09-14。状态：已批准的生产设计；本文件定义下一轮实现与上线验收，不宣称服务已经接通。

## 产品承诺

去大自然里把一次真实观察变成可保存的收藏卡。实拍照片、用户确认和服务来源必须分开表达；卡面工艺、手绘装饰和星级都不是物种鉴定或保护等级。任何网络、鉴别、生成、下载或导出失败，都保住照片和草稿，并如实说明失败。

当前有效入口是根目录的 `app.js`、`app.json`、`app.wxss` 与 `native/`。历史 `src/dist` 不参与生产页面。本方案不允许伪造账户、附近距离、识别置信度、云同步、赠送成功或订阅权益。

## 信息架构：三个 Tab

底部导航收敛为三个一级入口，拍摄是「探索」里的唯一主动作，而不是第四个 Tab：

| Tab | 任务 | 首屏内容 | 数据边界 |
| --- | --- | --- | --- |
| 探索 | 开始一次观察 | 山林插画封面、品牌宣言、巨型“拍一张”、相册导入、附近生境、今日收集、当季推荐 | 今日收集仅取本地 `createdAt` 为今天的卡；推荐只取已有物种资料中未收藏项；没有数据就显示空态 |
| 博物志 | 浏览与整理收藏 | 实体收藏卡网格、物种资料、次级筛选与搜索、卡片详情 | 筛选不占探索首屏；仅显示本地卡和已有资料 |
| 我的 | 管理个人记录 | 本地身份印记、已收集物种数、卡数、观察日数、笔记与草稿、备份/低动效/清除 | 未登录或未接云时统一叫“本地收藏”，不显示假等级、积分或订阅 |

「附近」是探索中的生境观察指南页或底部抽屉，不读取其他人的记录。没有用户主动授权并接通定位时，不显示定位、距离、坐标或“多少种在附近”。默认文案为“依据物种资料整理的生境观察指南”。

## 视觉语言

整体用暖米白纸张、深墨绿文字和低饱和赭石作为主色；薄荷绿只用于成功、确认和短时高亮。避免通用白卡堆叠、彩色 SaaS 仪表盘和持续闪烁。

探索首屏以静态山林插画和纸纹为背景，标题为「去大自然里」，宣言短而安静。主相机按钮占最强视觉权重；“相册导入”“附近生境”是并列次入口。今日收藏保持横向实体卡缩略，空槽低对比且有可理解的拍摄引导。当季推荐展示已有资料，不把推荐说成实时发现。

## 收藏卡：正面不变，背面更饱满

### 正面

正面继续采用既有 `collectible` 母版，而非杂志封面：真实照片为主、精细双层实体边框、编号、工艺章、中文名、拉丁名和固定五个星位。旧卡的 1–4 星保留原值，第五位为空；没有数据迁移把旧卡升级为五星。星级仅表示产品内收藏等级，不表示濒危等级、稀有度或置信度。

卡面缩略和详情必须共同消费同一展示模型，因此照片裁切、编号、工艺、星位、中文名和拉丁名完全一致。照片缺失时显示可恢复的“原图不可用”状态，不能用粉红底或替代物种图伪装原图。

### 背面

背面固定为一页纸质博物志，不含 `scroll-view`，并以物种专属手绘插画作为大面积构图背景。现有七种资产映射固定为：翠鸟、白鹭、朱鹮、红腹锦鸡、麻雀、绿尾大蚕蛾、山茶；每种使用不同插画。插画是装饰与辅助辨认，不是鉴别证据。

一页从上到下只保留：物种名/学名、一个短辨识要点、生境与季节、保护信息、编号与观察日期。长篇知识移到「完整资料」页；名称和保护级别优先完整显示，必要时缩短次级标签而不裁掉关键信息。保护区固定在底部安全区，正文绝不压入插画区。卡背与导出使用相同 `speciesId → illustration` 映射；找不到插画时显示共享的低对比线稿降级，不显示另一物种图。

## 开牌、翻牌与 3D 查看

开牌为一次性四段动效，全部可由“减少动态效果”降级为直接呈现：

1. **封签静候（0–420ms）**：用户按住或点按封签，显示可取消的纸质压印反馈。
2. **纸封裂开（420–700ms）**：封签分开，短暂露出边框；触摸取消或返回立即复原，不创建重复卡。
3. **卡片抬起（700–1,020ms）**：实体正面抬升、轻微高光掠过；只有本次确认卡可见。
4. **落版揭晓（1,020–1,260ms）**：卡片停在可读位置，显示“收入博物志”；重复触发被锁定。

3D 查看是纯净的全屏沉浸层，默认不自动覆盖详情页。详情页的“查看实体卡”明确打开它；关闭仅回到原详情位置。沉浸层中只呈现卡、翻面提示、关闭与保存/分享，不混入底下的列表、面板或可点击控件。短按翻面，拖动超过 8px 只跟手不误翻；`touchcancel` 归位。低动效时直接换面，内容和按钮不减少。

## 识别、插画生成与 CloudBase

生产路径为：拍摄/相册选择 → 本地保存草稿 → 用户同意上传 → CloudBase Storage 私有对象 → 云函数鉴别 → 用户确认候选 → 创建卡 → 可选生成手绘背景。客户端不直接持有百度或图生图供应商密钥。

`recognition` 状态契约保持如下：

```js
// native/contracts/services.js
recognizeObservation({ requestId, observationId, photoFileId, idempotencyKey })
// => { status: 'recognized' | 'needs_confirmation' | 'unknown' | 'failed',
//      candidates: [{ speciesId, confidence, source }], message }
```

本地或云端未配置时，`available:false`，界面展示“真实鉴别尚未接通”，可继续手动选种但明确标记为“用户确认 / 本地记录”。服务结果超时、换图、取消、删除草稿后均失效；低置信度要求候选确认；未知不强迫给答案。CloudBase 云函数调用百度智能云的鉴别接口，密钥仅保存在云函数环境变量；函数只返回需要的候选、来源和置信度。

手绘背景由国内供应商适配器在云函数侧调用。首个生产适配器固定命名为 `aliyunWanx`，只接受用户确认后的照片与已确认 `speciesId`，并把“照片经图生图服务处理”的授权单独记录。生成结果只能作卡背装饰，失败时保持本地七种插画或无装饰的纸张版，不影响已确认物种与收藏。供应商返回、轮询超时或内容安全拒绝都返回明确失败状态且保留草稿。

## 导出与分享

屏幕、分享长图、打印正面、打印背面都从同一个 `presentCard(card)` 模型取值。导出前必须依次完成照片和插画的 Canvas 解码，`onload` 后才绘制；`onerror`、十秒超时、页面卸载、文件删除或代次失效都禁止生成文件，清空旧导出路径并显示“照片无法读取，请重新选择或恢复照片后重试”。不能导出粉红底、空白成品或旧缓存。

显式“导出含照片分享图”先提示用户。微信资料分享只发公开物种资料和公共图片，不携带原图、笔记、精确地点、卡号或识别来源。打印规格保持 300dpi、821×1121px 成品框、750×1050px 裁切区、3mm 出血；输入照片 DPI 低于目标时提示清晰度不足，不伪称可补细节。

## 好友赠送

赠送只在双方已用微信身份登录、都同意接收、云端服务接通后出现。云函数通过不可猜测的礼物 ID 和一次性领取事务变更归属，幂等地返回 `created`、`claimed`、`expired` 或 `rejected`。送出的是一张可赠送的收藏记录副本或明确的转让记录，绝不默默传递私人原图、笔记、地点或导出文件；对方领取前再次展示隐私范围。未接通时入口显示“好友赠送尚未开放”，不展示成功动画。

## 隐私、失败与发布边界

照片、可能的定位和生成图片都采用最小化收集：默认不定位；识别/生成上传均要单独同意；CloudBase 对象为私有读写、短期签名访问；用户可删除本地、云端原图和派生图。删除操作先本地标记，再以可重试任务清理云存储与数据库，失败时告知尚待清理而非假称完成。

上线前完成微信小程序主体认证、服务器域名配置、ICP备案（如部署形态要求）、隐私保护指引、第三方 SDK/服务披露、内容安全、审核材料与真实设备验收。没有真实微信、CloudBase、百度或图生图账号证据前，不称线上识别、生成、赠送、同步或发布已可用。
