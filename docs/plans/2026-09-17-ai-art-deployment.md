# AI 艺术制卡验证与发布边界

本次只修改本地代码，不部署、不读取密钥。真实艺术制卡还需要运行环境中的新版 natureAI2；旧函数不认识 art_photo 风格时会继续旧风格，不能把本地测试通过等同于真机效果通过。

## 用户控制台步骤
1. 在该小程序的现有 CloudBase 环境部署 cloudfunctions/natureAI2（云端安装依赖）。
2. 保留服务端 DASHSCOPE_API_KEY 环境变量，在控制台确认所用图像编辑模型已开通；不要发送密钥到聊天。DASHSCOPE_MODEL 需与当前 image2image/image-synthesis 接口兼容。
3. recognizeObservation 必须是支持 upload_ticket / register_asset 的已更新版本。assets、aiTasks 保持服务端拥有者校验，不放开客户端任意写入。
4. 本轮开发工具签名问题若仍存在，请从云控制台发布函数，不能依据 CLI exit 0 判断成功，需看到函数部署成功状态。
5. 前端重新编译/预览后，在真机先测试直接制卡，再测试 AI 艺术制卡和断网降级。检查原图仍可恢复，卡背可离线显示，减少动态效果下没有震动。

## 已有本地证据与未验项
29 个 Node 测试通过；原生构建和官方模板编译通过。服务器调用使用假适配器测试，未调用真实付费生成服务；真实模型可用性、费用、生成效果、真机 SVG 支持仍待上述测试。
官方插画优先用既有共享缓存；缓存失败显示来自项目现有线稿的本地 SVG。陌生物种用通用植物纹样作装饰，不声称它是该物种精确插画。
